## 2. Path: the stages

The ladder is: one node of one (the operator's own key), then two of two; afterwards the set grows automatically with
powerful nodes entering with their total in ang as stake. The seedified network with a signed upgrade from any node is the
next step; the council takes the key later. Each stage names what it guarantees,
its passage condition as a command or test file that exits 0, the one line the user is told, the code it adds and the
code that exists. "to be written" means the test does not exist yet. A stage is passed when its condition is green and
recorded in site/docs/qa/; from Stage 4 (the set grows past 2) the scale gate R4.9 is an extra condition of every stage, while Stages 0 to 3 run the shapes n = 1 (t = 1) and n = 2 (t = 2) only and no scale battery; assertions (e), (f), (g) and the runtime cid, the list version and the runtime-record values digest of the release record are asserted only from the stage that ships the runtime (Stage 5), so at Stage 4 the battery asserts (a) to (d) and (h). Code for a later stage may be written and tested before (red first), never deployed before.

Stages 0 and 1 are one procedure: the 1-of-1 rebirth of the network with the operator of the first node alone (the runbook's Build A and Build B). Stage
2, the seedified network with a signed upgrade from any node, follows right after it, before the set grows.
